一个没有记忆的聊天模型，每次见面都像第一次见面。你刚花半小时解释完研究背景，打开新对话，又得从头再讲一遍。

Claude 的记忆功能想解决的就是这种断裂感。但它并不是把所有旧聊天一股脑塞进新的提示词。更准确地说，它在不同时间尺度上用了几种不同的办法，让过去在需要时重新进入现在。

> 下面的“三层结构”是我根据 Claude 官方功能说明整理出的理解模型，不是 Anthropic 公布的底层系统架构。

## 记忆不是无限增长的上下文

最容易产生的误解是：既然 Claude 记得以前的事，那么模型的上下文窗口里一定装着我们的全部历史。

这既昂贵，也没有必要。十个月前关于旅行计划的对话，不应该在今天调试代码时一直占据注意力。一个实用的记忆系统，重点不是保存得越多越好，而是让正确的过去在正确的时候出现。

我更愿意把它理解成三层：当前对话、历史检索和长期记忆。

## 三层连续性

### 当前对话：工作记忆

当前聊天里的消息、文件和工具结果构成最直接的上下文。它像书桌：正在处理的材料都摊在眼前，模型可以连续推理，但空间终究有限。

### 历史检索：需要时再回头找

当你问“我们上次讨论的训练方案是什么”时，Claude 可以搜索过去的聊天，找到相关片段，再把它们带回当前对话。官方说明明确提到，这一过程使用检索增强生成（RAG），并会以工具调用的形式出现。

这更像档案馆，而不是人的潜意识：旧内容平时不占桌面，需要时才被取出，而且可以追溯到原来的对话。

### 长期记忆：持续更新的条目

Claude 还会从聊天中形成更稳定的记忆，例如你的角色、项目背景、沟通习惯、技术偏好和持续进行的工作。按照官方说明，这些记忆被组织成分类条目，并会随着对话实时读取、写入和更新，而不是每天定时做一次总摘要。

因此，“记住我喜欢简洁的回答”和“找出三个月前那段代码”是两种不同动作：前者使用稳定的记忆条目，后者更适合搜索原始聊天。

## 项目边界比记忆容量更重要

Claude 的每个 Project 都有独立的记忆空间和项目摘要。一个论文项目里形成的背景，不会自动混进旅行计划或另一个代码库。

这种隔离很重要。真正危险的不是模型忘记一点东西，而是它在错误的场景里想起了正确的信息。项目边界让记忆拥有作用域，就像程序里的局部变量：离开当前空间，它就不应该继续影响判断。

## 记住，也要允许忘记

记忆功能只有在用户能够检查和修改时才可信。Claude 允许在设置中查看分类后的记忆，单独修改或删除条目，也可以暂停记忆或彻底重置。Incognito chat 则不会进入记忆或聊天历史。

这里有个容易忽略的细节：删除一段原始对话，并不一定自动删除已经从中提炼出的记忆条目。若某条信息不应继续保留，还需要在 Memory 面板中检查和删除对应记忆。

## 从“回答机器”到长期合作者

我喜欢这套设计，是因为它没有把记忆假装成一个神秘、无限的脑袋。当前上下文负责眼前的问题，检索负责找回证据，长期条目负责维持稳定偏好，Project 则划定边界。

记忆真正改变的不是单次回答的智力，而是协作的启动成本。下一次打开 Claude 时，我们不必重新搭建整个世界，只需要继续向前走。
